# 存储治理闭环加固设计

## 目标

在不扩大业务范围的前提下，修复日志清理的数据丢失风险、容量状态误报、维护线程生命周期缺陷和接口字段错位风险，并补齐可复验测试。保持现有日志清理入口、存储卡片布局、保留周期和服务启动方式不变。

## 架构设计

### 1. 日志安全落库

- 将日志缓冲刷新改为返回错误。
- 刷新时暂取当前批次；写入成功后结束，写入失败时把失败批次按原顺序重新放回缓冲区前部。
- 手动清理和自动保留任务必须在刷新成功后才能进入聚合与删除事务；刷新失败直接返回错误，不删除任何日志。
- 保持现有批量写入、SQLite 事务和 PostgreSQL 批处理实现，不引入新队列或外部依赖。

### 2. 容量快照契约

- 使用具名的容量快照结构替代 12 个位置返回值，避免同类型字段静默错位。
- 磁盘采样或任一受管目录采样失败时，快照状态统一为 `unknown`，同时保留已成功采集的数据和错误说明。
- PostgreSQL 数据库文件容量明确为未知，不伪装成 SQLite；S3 模式只统计仍位于本地的历史图片占用，并以文案说明其含义。

### 3. 维护线程生命周期

- `Start`、`Stop` 均支持重复及并发调用。
- `Stop` 在未启动时立即返回；已启动时关闭统一上下文并等待任务退出。
- 清理和采样使用可取消上下文，服务停止时不再等待固定的五分钟清理超时。
- 清理与采样保持单实例，避免重复任务并发删除或重复扫描。

### 4. 前端状态与文案

- `normal`、`warning`、`critical`、`unknown` 四种状态独立展示；`unknown` 不使用绿色正常样式，也不展示伪造的零值。
- 移除“盘已用”“SQLite”等硬编码，全部通过中英文翻译键和数据库驱动生成。
- 保留当前专用双栏卡片布局，不进行无关视觉重构。

## 数据流与错误处理

1. 请求日志进入内存缓冲。
2. 清理任务先刷新缓冲；失败则重新入队并终止清理。
3. 刷新成功后，在数据库事务内聚合基线并删除过期记录。
4. 容量采样生成具名快照；任何局部失败均返回 `unknown + error`。
5. 管理接口透传快照，前端按状态和数据库驱动精准展示。

## 测试设计

- 日志写入失败时缓冲数据不丢失，且清理事务不执行。
- `Stop` 未启动、重复调用和清理期间停止均可安全返回。
- 目录不可读或容量采样失败时状态为 `unknown`。
- 管理接口具名字段映射正确，未注入快照时返回未知状态。
- 前端覆盖未知状态、四级色调、中英文文案及 SQLite/PostgreSQL 标签。
- 最终运行全量 Go 测试、竞态检测、静态检查、前端类型检查与生产构建；既有续链随机失败必须单独定位并稳定后才允许提交。

## 部署与回滚

- 构建候选 EXE 后先验证哈希和健康检查，再按项目热替换规则替换运行实例。
- 若启动或健康检查失败，恢复旧 EXE；数据库结构不新增字段，不需要迁移回滚。

## 非目标

- 不重构完整日志系统，不引入消息队列。
- 不改变日志保留天数、统计口径或仪表盘刷新策略。
- 不调整存储卡片以外的仪表盘视觉与交互。
