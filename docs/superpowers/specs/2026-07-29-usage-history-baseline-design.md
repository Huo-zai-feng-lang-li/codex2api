# 使用统计历史累计基线设计

## 目标

将使用统计的历史累计基数设置为：

- 总 Token：5,000,000,000
- 用户累计计费：10,000 USD

后续真实请求继续在该基数上累加。

## 边界

- 仅更新 `usage_stats_baseline_v2` 中 `id = 1` 的 `total_tokens` 与 `user_billed`。
- 不写入、删除或修改 `usage_logs`。
- 不修改 `account_billed`、请求数、输入/输出 Token、缓存、延迟等其他统计字段。
- 不修改代码、配置、API Key 配额或账号用量窗口。

## 数据影响

- 仪表盘累计总 Token 与累计用户计费变为“设定基数 + 当前 `usage_logs` 聚合值”。
- 日志列表、趋势图、今日统计、模型/API Key 明细、5 小时与 7 天滑动窗口保持真实数据。
- 累计总数将无法与现存请求日志逐条对账，这是已确认的展示口径。

## 执行与回滚

1. 识别当前运行实例实际使用的数据库。
2. 备份数据库或记录基线原值。
3. 在事务内更新两个目标字段。
4. 查询基线并调用统计接口验证最终累计值。
5. 若验证失败，事务回滚；若需人工撤销，恢复记录的原值。

## 验收

- `usage_logs` 行数及内容不变。
- 统计接口累计值符合“基线 + 现有真实日志”的计算语义。
- 今日、趋势、API Key 配额统计不因本次变更发生变化。
