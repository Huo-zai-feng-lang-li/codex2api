# OAuth 账号代理与刷新取证

## 目标
- 核实 5 个 OAuth 账号的代理配置、AT/RT 状态、刷新失败原因。
- 避免直接手工刷新导致 RT 轮换后没有落库。

## 已取证
- 当前服务进程监听 `127.0.0.1:18080`，健康检查 `/health` 返回 `available=2,total=10`。
- 本机 dotsvpn 实际监听 `127.0.0.1:51081`，`127.0.0.1:5108` 不可用。
- 5 个 OAuth 账号为 DB ID `585,586,587,588,589`，均有 `refresh_token`，均无 `access_token`。
- 运行态账号列表显示：
  - `585 spark_8773` 代理为 `http://127.0.0.1:5108`
  - `586 fern.6173` 未配置代理
  - `587 jamie7fa1` 未配置代理
  - `588 fern_231` 未配置代理
  - `589 rileya184` 代理为 `http://127.0.0.1:5108`
- 日志映射：启动并行刷新里的序号 `6..10` 对应 DB ID `585..589`。
- 近期日志显示：
  - 走 `5108` 的账号出现 `proxyconnect tcp: dial tcp 127.0.0.1:5108` 连接失败。
  - 未走代理的账号出现 `unsupported_country_region_territory`。

## 结论
- 不能用当前“测试连接失败”判断 RT 已过期，因为 5 个账号都缺 AT。
- 当前失败主因是代理出口配置错误或缺失：实际可用端口是 `51081`，不是 `5108`。
- 若要继续验证 RT 是否有效，应先将 5 个 OAuth 账号统一改为 `http://127.0.0.1:51081`，再通过服务自带刷新接口触发刷新，让新 AT/RT 自动落库。

## 待确认
- 用户已选择方案 1：允许把 `585..589` 的代理统一改成 `http://127.0.0.1:51081` 并触发刷新。

## 执行结果
- 已通过管理接口更新 `585..589` 的 `proxy_url` 为 `http://127.0.0.1:51081`，数据库与运行态均同步成功。
- 已通过管理接口批量刷新 `585..589`，结果为 `success=5, failed=0`。
- 刷新后 5 个账号均为 `active`，均存在 `refresh_token`、`access_token`、`expires_at`，错误信息为空。
- 健康检查从取证阶段的 `available=2,total=10` 提升为 `available=7,total=10`。

## 当前结论
- 这批账号的 RT 没过期。
- 之前不可用的核心原因是代理端口写错或缺失：实际 dotsvpn 端口为 `51081`，不是 `5108`。

## 2026-06-08 代理边界修正
- [已取证] 当前数据库 `system_settings.proxy_url` 为空；普通账号业务链路代码优先级为 `账号 proxy_url > 粘性代理池 > 全局 ProxyURL > 直连`。
- [已实施] OAuth 添加账号表单的代理默认值固定为 `http://127.0.0.1:51081`，不再读取系统全局代理作为兜底。
- [已实施] OAuth 回调换 token 不再回退到系统全局代理；OAuth session 没有独立代理时直接提示“OAuth 授权代理地址为必填”。
- [已实施] 设置页全局代理文案改为“账号未配置代理时才使用的全局兜底；留空则直连”，避免误解为仅新增账号默认值。
- [已实施] Refresh Token、Session Token、Access Token 新增表单默认填入 `http://127.0.0.1:51081`；API Key 新增表单继续默认空代理，避免误伤国内中转站。
- [已实施] 代理管理页新增“代理入口与生效规则”说明，明确账号单独代理、普通代理池、全局代理、OAuth 代理、Resin 粘性代理池的入口、优先级和注意事项。
- [已实施] 使用文档与部署文档新增 Windows 本地启动入口说明：推荐桌面快捷方式或 `start-codex2api.bat`，不建议直接双击 `codex2api.exe`。
