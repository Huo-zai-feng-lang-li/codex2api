# Responses 高并发内存治理计划

## 目标

在不改变普通 `/v1/responses` 请求、账号调度、重试和流式响应语义的前提下，消除续链完整历史缓存的平方级重复占用，并为进程级请求内存与本地历史回退建立明确上限。

## 设计

- 连续性缓存改为不可变父链节点：每个响应只保存本轮 `input`、本轮 `output`、父响应 ID 和 owner，分叉共享祖先，回放时再完整物化。
- 缓存只按完整会话树驱逐，禁止删除祖先后继续回放残缺历史；超限时保留 owner、关闭本地回放能力。
- 新增进程级 Responses 请求准入：同时限制在途请求数和请求体字节，失败时明确返回本地压力错误，不进入账号调度或上游链路。
- 新增本地完整历史回退并发上限：仅限制 fallback，普通无状态请求不受影响；饱和时明确失败，禁止静默退化为新对话。
- `/health` 增加只读内存治理指标；限制支持环境变量配置，默认值兼顾单机与小团队部署。

## 验收标准

- 长链缓存字节按唯一轮次线性增长，分叉不复制公共祖先。
- 缓存缺失、驱逐、超限或 fallback 饱和时不发送残缺历史。
- 普通请求的请求体、上游次数、流式响应和重试行为保持原样。
- 并发下计数不超限、不为负数、无数据竞争。
- 全量 Go 测试、构建、健康检查和两轮续链验收通过。
