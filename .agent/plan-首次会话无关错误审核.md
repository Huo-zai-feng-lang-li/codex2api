# 首次会话无关错误审核计划

## 目标
- 确保用户在“首次会话”使用时，不会看到与真实业务无关的错误文案或内部细节。
- 统一 HTTP `/v1/responses` 与 WebSocket `/v1/responses` 在首会话上的行为，避免分叉实现导致的异常提示。
- 让首会话在上游失败时要么稳定重试，要么统一收口为可理解的终态错误，不挂死、不泄漏内部实现细节。

## 已验证事实
- WebSocket 首会话之前曾额外发送 `Conversation_id`，HTTP 路径只发送 `Session_id`，现已统一。
- `proxy/responses_ws.go` 已改为使用与 HTTP 相同的账号选择器与重试排除逻辑。
- 已有回归测试覆盖：
  - 首包前流断流后返回 `response.failed`
  - 首会话可切换到 HTTP fallback
  - 首次账号执行前 `no_available_account` 不应直接泄漏到客户端
- 全仓库 `go test ./...` 已通过，`codex2api.exe` 已重建并重启，`/health` 正常。

## 风险点
- 首会话的问题主要集中在 WebSocket 入口和上游流式断流收口，不应再只盯单一 `no_available_account` 文案。
- 首会话如果再次报错，优先核查是否为：
  - 客户端实际走的是 WS 而不是 HTTP
  - 首条请求头是否携带了额外 session 相关字段
  - 内部断流是否被错误归因为客户端断开

## 下一步
1. 继续观察真实首会话流量，确认是否还出现无关错误文案。
2. 如果再次复现，抓服务端日志与首条请求头，定位是 WS 入口、账号调度还是上游断流收口。
3. 必要时再细分“首次会话错误”成独立测试套件，专门盯首包前终态是否可见。
