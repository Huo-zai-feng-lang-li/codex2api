# 当前活跃请求 SSE 实时推送计划

## 目标

- 请求开始访问上游后立即出现在管理仪表盘。
- 请求结束、失败、取消或切换重试账号后立即从仪表盘消失。
- 不修改 Responses 续接、账号选择、换号、重试排除或 WS/HTTP fallback 逻辑。

## 架构

1. `auth.Store` 在现有 `BeginActiveRequest` / `EndActiveRequest` 状态变更后发送非阻塞通知。
2. 管理端新增受 `adminAuthMiddleware` 保护的 SSE 接口。连接建立和每次通知后均发送完整快照，重连无需回放增量历史。
3. 前端通过带 `X-Admin-Key` 的 `fetch` 读取 SSE，断线自动重连；不用原生 `EventSource`，避免把管理密钥放进 URL。
4. 前端以服务端 `duration_ms` 为基准，用本地单调时间刷新已耗时；后端不发送每秒快照。
5. 仪表盘原 15 秒轮询继续负责其他统计，但不再覆盖 SSE 管理的活跃请求状态。

## 实施阶段

### 阶段一：后端事件源

- 为 `auth.Store` 增加有界、非阻塞、可退订的活跃请求变更订阅。
- 先写订阅、合并通知、退订测试并确认失败，再实现。
- 通知不得持有活跃请求锁，不得阻塞代理请求。

### 阶段二：管理 SSE

- 新增 `GET /api/admin/runtime-status/active-requests/events`。
- 首包和变更包使用 `event: snapshot`，内容包含完整 `active_request_details`。
- 每 15 秒发送 SSE comment 心跳；断连时停止 ticker 并退订。
- 覆盖鉴权、首包、开始/结束推送和断连清理测试。

### 阶段三：前端订阅

- 新增 SSE 解析器与活跃请求订阅 Hook。
- 解析器覆盖分块、CRLF、多行 data 和不完整尾包。
- Hook 负责取消、重连和快照替换；页面卸载后不得继续重连。
- 活跃请求面板本地刷新已耗时，空列表时不创建计时器。

### 阶段四：请求记录迁移

- 将“使用统计”页面的请求记录列表提取为独立组件，保留现有筛选、分页、刷新和数据接口。
- 在仪表盘“当前活跃请求”下方挂载请求记录列表。
- “使用统计”页面仅移除请求记录列表，统计摘要、图表及其数据加载逻辑保持不变。

### 阶段五：闭环验证

- 后端定向测试、前端测试、类型检查、构建、`go test ./... -count=1`、`go vet ./...`。
- HTTP 与 WebSocket 请求开始/结束实时展示。
- 重试换号时旧记录结束、新记录出现，最终归零。
- 验证 Responses 包 A -> previous_response_id 包 B 续接不回归。
- 检查 SSE 断线后订阅、goroutine 与后台进程全部释放。
- 不构建或替换 Windows 服务 `exe`，现有运行服务保持不动。

## 影响边界

- 允许修改：活跃请求运行态存储、管理路由、管理前端数据层与面板。
- 禁止修改：续接缓存、session affinity、账号调度、retry exclusions、上游请求转发与 fallback 判断。
- 当前工作区已有修改全部保留；所有补丁按现有内容窄范围叠加。
